# VestNaija

VestNaija is a Django prototype for a Nigerian demo investment wallet and IPO trading platform.

The application runs in demo/sandbox mode only:

- No real money is accepted.
- No real securities are traded.
- No SEC, NGX, CSCS, bank, broker, or Dangote Refinery API integration is claimed or implemented.
- Future real integrations should be added through the provider interfaces after licensing, authorization, credentials, and official documentation are available.

## Local Setup

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

If PostgreSQL environment variables from `.env.example` are present, Django uses PostgreSQL. Without them, it falls back to local SQLite for development and tests.


## Deploying to Render

A `render.yaml` blueprint is included (New → Blueprint in the Render dashboard,
pointing at this repo). It provisions a Postgres database and a web service
running `gunicorn`, and declares the required environment variables. Secrets
(`FLW_PUBLIC_KEY`, `FLW_SECRET_KEY`, `FLW_ENCRYPTION_KEY`, `FLW_SECRET_HASH`,
`EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`)
are marked `sync: false`, so enter them in the Render dashboard yourself after
the blueprint is created — never commit them. If `EMAIL_HOST` is left blank,
verification emails are only logged to the server console instead of
actually being sent, so set it (and the matching SMTP credentials) before
relying on email verification in production.

`DJANGO_SECRET_KEY` is auto-generated by the blueprint. `ALLOWED_HOSTS` and
`CSRF_TRUSTED_ORIGINS` pick up Render's external hostname automatically.

A KYC approval no longer sends its "you're verified" email right away — it's
queued for 24 hours later. The blueprint's `vestnaija-kyc-email-cron` job
runs `python manage.py send_due_kyc_emails` every 15 minutes to flush the
queue. Render Cron Jobs need a paid plan; on the free tier, trigger that
command periodically some other way instead (e.g. a scheduled task on
another host, or run it manually while testing).

## Login Key

Every user gets a unique login key, shown on their dashboard, that logs
them straight in from `/login/key/` without a password. Treat it like a
password: anyone with it can access the account. Users can regenerate it
from the dashboard at any time, which immediately invalidates the old key.

After deploying, point Flutterwave's webhook (dashboard → Settings →
Webhooks) at `https://<your-render-domain>/payments/webhook/`, with the
"Secret Hash" field set to the same value as `FLW_SECRET_HASH`.
